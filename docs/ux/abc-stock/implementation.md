# ABC UI ที่พัฒนาแล้ว

สถานะ: frontend slice ตาม layout 2 และ Clear Blue โหมดเดียว มือถือพื้นขาว
ใช้ Ant Design 6.6.6 กับ React 18 ของแอปปัจจุบัน

## ทดลองใช้งาน

เปิดแอปด้วยขั้นตอนใน [README หลัก](../../../README.md#run-locally) แล้วเข้าสู่ระบบ
ด้วยบัญชี staff หรือ admin หน้าแรกหลังเข้าสู่ระบบคือ **วิเคราะห์ ABC**
บัญชีและรายชื่อผู้ใช้ของ admin ยังเชื่อม API auth เดิม

1. เริ่มจากช่วงข้อมูลตัวอย่าง 20 ก.ค.–17 ต.ค. 2026 ซึ่งมีสินค้า 8 รายการ
2. เลือกสินค้าจาก radio หรือชื่อสินค้าในตาราง บนจอแคบจะเปิด Drawer
3. เลือกช่องว่างในโซนที่ตรงกับกลุ่ม ABC แล้วกด **เตรียมรายการย้าย**
4. ตรวจต้นทาง ปลายทาง และจำนวน ตำแหน่งยังไม่เปลี่ยนในขั้นเตรียม
5. ทำเครื่องหมายยืนยันการย้ายครบ แล้วกด **ยืนยันการย้ายสินค้า**
   ตำแหน่งในข้อมูลตัวอย่างจึงเปลี่ยน ส่วนจำนวนสินค้ายังคงเดิม
6. หากยังไม่ได้ย้ายจริง สามารถยกเลิกรายการเพื่อคืนช่องว่าง

เลือกช่วงวันที่อื่นแล้วกด **วิเคราะห์ใหม่** เพื่อคำนวณใหม่จากใบเบิกตัวอย่าง
ตัวกรองทั้งหมด/ควรย้าย/รอยืนยันใช้ดูงานที่ต้องทำต่อได้
สินค้าที่ไม่มีประวัติไม่ถูกจัดเป็นกลุ่ม C และไม่ถูกเสนอให้ย้ายอัตโนมัติ

## ขอบเขตข้อมูล

- สินค้า ใบเบิก และงานย้ายเป็นข้อมูลตัวอย่างในหน่วยความจำของ frontend
  สลับไปหน้าบัญชีแล้วกลับมา งานย้ายยังอยู่ แต่รีโหลดหรือออกจากระบบจะเริ่มใหม่
- ยังไม่มี inventory API หรือการบันทึกสินค้า/งานย้ายลง MongoDB
- จำนวนครั้งเบิกนับแต่ละสินค้าไม่ซ้ำต่อใบเบิกที่จ่ายสำเร็จภายในช่วงวันที่
  ผลรวมความถี่สินค้าไม่ใช่จำนวนใบเบิกไม่ซ้ำ และไม่ได้ใช้จำนวนชิ้นจัดอันดับ
- ใช้เกณฑ์สะสม 80/95 เพื่อสาธิตเท่านั้น จุดตัดและคะแนนเท่ากันยังต้องตกลงก่อนทำ backend จริง
- การกันช่องระหว่างรอยืนยันเป็นข้อเสนอ UX ในชุดทดลอง ยังไม่ใช่ข้อตกลง concurrency
  ระหว่างผู้ใช้จริง การเตรียมและยืนยันมีการตรวจช่องซ้ำ/ต้นทาง/จำนวนใน model ตัวอย่าง
- ไม่มีตัวสลับ light/dark mode

## โครงสร้างและ responsive

- `frontend/src/inventory/model.ts`: fixture, วิเคราะห์ความถี่, ช่องว่าง และกติกาย้ายตัวอย่าง
- `frontend/src/inventory/AbcWorkbench.tsx`: Table, Segmented, RangePicker, Select, Form,
  Checkbox, Alert และ Drawer จาก Ant Design
- `frontend/src/theme/clearBlue.ts`: theme และ component tokens
- `frontend/src/pages/Workspace.tsx`: เมนู บัญชี สิทธิ์ admin และ state ตัวอย่างตลอด session
- ฟอนต์ IBM Plex Sans Thai เก็บใน `frontend/public/fonts/` พร้อม OFL license

ตั้งแต่ 1200px ขึ้นไปแสดงแผงข้าง; จอแคบกว่านั้นเปิด Drawer จากสินค้า
ต่ำกว่า 992px ยุบเมนู และบนมือถือย้ายสถานะมาใต้ชื่อสินค้าเพื่อเห็นครบโดยไม่เลื่อนแนวนอน
โครง auth, refresh และสิทธิ์ server ใช้ของเดิม หน้า login/บัญชีเปลี่ยนเป็น Ant Design
และใช้ธีมเดียวกับพื้นที่ทำงาน

## Validation

- `yarn test`: 11 tests รวม auth เดิม การนับครั้งเบิก และข้อกำหนดการย้าย
- `PLAYWRIGHT_CHANNEL=chrome yarn test:e2e`: 4 browser workflows รวมวันที่/empty state,
  การเตรียมและยืนยัน, mobile cancellation/navigation, auth cross-tab และ role enforcement
- `yarn build`: TypeScript และ production build ผ่าน มีคำเตือนขนาด JavaScript chunk
- ตรวจภาพ desktop 1440px, tablet 1024px และ mobile 390px; ไม่มี page overflow บนมือถือ

คำสั่งทั้งหมดรันใน `frontend/` Browser tests ใช้ API/MongoDB แยกจากข้อมูล local
การตรวจ UI ใช้ auth response จำลองเฉพาะใน capture script ไม่ได้เพิ่มทางข้าม auth ลงแอป
