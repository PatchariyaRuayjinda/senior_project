# ABC และการย้ายตำแหน่งสินค้า

ใช้เลย์เอาต์ตาราง ABC กับแผงรายละเอียดด้านข้าง (แบบ 2 ที่ตกลงไว้)
บนจอแคบแผงเปลี่ยนเป็น Drawer เต็มความกว้าง ใช้ component มาตรฐานของ
Ant Design และธีม Clear Blue โหมดเดียว มือถือใช้พื้นหลังสีขาว

ดู [การทำงาน ขอบเขตข้อมูล และผลตรวจ](implementation.md),
[ข้อกำหนดผลิตภัณฑ์](../../../PRODUCT.md) และ [แนวทางออกแบบ](../../../DESIGN.md)

## กติกาที่ตกลงแล้ว

- เจ้าหน้าที่คลังทำงานรับเข้า เบิก วิเคราะห์ และเลือกตำแหน่งได้ครบ
- ABC จัดอันดับตามจำนวนครั้งที่เบิกของแต่ละสินค้า ไม่ใช้จำนวนชิ้นหรือมูลค่า
- ใบเบิกมีหลายสินค้าได้ แต่ละสินค้านับหนึ่งครั้งต่อใบที่จ่ายสำเร็จ
- ค่าเริ่มต้นของผลิตภัณฑ์คือย้อนหลัง 90 วัน และเลือกช่วงวันที่เองได้
- `A01` คือโซน A ช่อง 01 หนึ่งช่องเก็บสินค้าหนึ่งชนิดได้หลายหน่วย
- แต่ละสินค้ามีตำแหน่งเดียวในรอบแรก
- สินค้าที่ไม่มีประวัติแสดงสถานะแยก ไม่จัดเป็น C หรือเสนอให้ย้ายอัตโนมัติ

## Workflow

1. วิเคราะห์ ABC และกรองสินค้าที่โซนปัจจุบันไม่ตรงกับกลุ่มที่แนะนำ
2. เลือกสินค้าแล้วเลือกช่องว่างในโซนที่ตรงกับกลุ่ม ABC
3. เตรียมรายการย้าย โดยแสดงต้นทาง ปลายทาง จำนวน และหน่วยให้ตรวจสอบ
4. ย้ายของจริงแล้วกลับมาทำเครื่องหมายและยืนยัน
5. เปลี่ยนตำแหน่งในระบบหลังยืนยันเท่านั้น จำนวนสินค้าคงเดิม

หากยังไม่ได้ย้ายจริง สามารถยกเลิกรายการเตรียมย้ายเพื่อคืนช่องว่างได้
ช่วงวันที่และสินค้าที่เลือกยังอยู่ในบริบทเดียวกับผลวิเคราะห์

## ขอบเขตปัจจุบันและเรื่องที่ยังต้องตกลง

- หน้า frontend ใช้ข้อมูลตัวอย่างในหน่วยความจำ ไม่ใช่ข้อมูลคลังจริง
- ช่วงเริ่มต้นของตัวอย่างถูกตรึงไว้ที่ 20 ก.ค.–17 ต.ค. 2026 เพื่อทดลองซ้ำได้
- ผลรวมความถี่ของทุกสินค้าไม่ใช่จำนวนใบเบิกไม่ซ้ำ
- รีโหลดหรือออกจากระบบจะรีเซ็ตสินค้าและงานย้ายตัวอย่าง
- ยังไม่มี inventory API หรือการบันทึกลง MongoDB
- เกณฑ์สะสม 80/95 ใช้สาธิตเท่านั้น ยังต้องยืนยันจุดตัดและกรณีคะแนนเท่ากัน
- การกันช่องระหว่างรอยืนยันเป็นข้อเสนอ UX ยังไม่กำหนดกติกา concurrency สำหรับผู้ใช้จริง
